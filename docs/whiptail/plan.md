и ручной ssh упираются в лимит 5 соединений в час, см. `эксплуатационные заметки проекта` §17.2).

## Лестница тестов (почему именно так)

1. **T0 headless (ALTAR).** `tests/whiptail-stub.sh` в `PATH`: перехватывает аргументы диалогов,
   отдаёт ответы из файла. Проверяет **поток управления** (ветки, валидация, отмена, `set -e`),
   а не картинку. Здесь ловится 90 % риска.
2. **T1 визуальный (dietpi, Debian 13).** `script -qec` даёт настоящий pty и TERM, транскрипт
   сохраняется. Проверяет геометрию, длинные строки, ESC/Cancel. Установки нет: гейт
   `QUESTIONS_ONLY=1` выходит до `apt-get`.
3. **T2 ifw, вопросы.** `ssh -t ifw 'QUESTIONS_ONLY=1 bash setup.sh'` — сверка сгенерированного
   `setup` с живым: сравниваются 47 ключей, пропускается `fixtures/skip-keys.txt` (21 ключ: `SETUP_DATE`, 12 `WARP_*`, 8 сетевых). Это проверка, что ответы
   профиля (включая `SSH_PROTECTION=n`) поданы заново и доехали до файла.
4. **T3 ifw, полная переустановка.** Только в отдельное окно, со снимком (см. безопасность),
   после успешных T0-T2, и только по команде «делай».

## Риски

| риск | почему | что делаем |
|---|---|---|
| `set -e` + `whiptail` exit 1/255 | первый «No» убивает установщик молча | все вызовы через `if ! …`, отдельный хелпер |
| нет TTY (`wget … \| bash`) | whiptail падает | детект `[[ -t 0 && -n $TERM ]]` → plain-режим |
| `whiptail` не установлен | минимальные образы | `apt-get install -y whiptail` до вопросов, при сбое plain-режим |
| потеря профиля при переустановке | `setup` перезаписывается из ответов, старый файл не читается | prefill **сознательно не внедряем** (решение 19.11.2026): логика «спросить и перезаписать» сохраняется; оператор отвечает вручную, эталон — `tests/answers/ifw.answers` |
| `read -e -i` (readline prefill) | у whiptail нет аналога | `--default-item`/`--defaultno` + документировать различие |
| 8 закомментированных include-списков | включение = новая функция, не UI | решение пользователя, по умолчанию оставить как есть |

## Решения (приняты пользователем 19.11.2026)

1. **Вариант A** — рендерер поверх исходного порядка вопросов; никаких разделов-меню
   и повторного редактирования. **Строго по структуре: 39 диалогов, по одному на вопрос.**
   Склейка однотипных, разделы и повторное редактирование — следующие версии проекта.
2. **Язык подписей — английский**, как в апстриме (`LC_ALL=C`).
3. **Структура исходного `setup` сохраняется полностью**: те же 39 вопросов в том же порядке, тот же текст, тот же порядок и состав ключей в файле `setup` (блок `:572-639` не трогаем).
4. **8 закомментированных include-списков не включаем** — остаются закомментированными, как в апстриме.
5. **Выбор интерфейса — вопрос, а не флаг** (решение пользователя 19.11.2026): до диалогов скрипт
   спрашивает «1) whiptail TUI 2) plain prompts»; вопрос рисуется `read -rp` (whiptail ещё не
   гарантирован), `AZ_UI`/`NO_WHIPTAIL` перекрывают его для тестов, а при отсутствии TTY вопрос
   не задаётся вовсе (сразу plain — вопрос без человека превращается в шум).
6. **Апстрим не читает старый `setup`** (дефолты вшиты в команды, файл перезаписывается из ответов) —
   эта логика сохраняется; никакого prefill/чтения `/root/antizapret/setup` не добавляем (решение
   пользователя, 19.11.2026).

  `:321`).
- `wt_textbox()` — сводка настроек: ширина `COLUMNS-4` (clamp 40..120), высота `LINES-4` (мин 12),
  `--scrolltext` всегда. Заменён `--textbox "$SETUP_PREVIEW" 24 78`.
