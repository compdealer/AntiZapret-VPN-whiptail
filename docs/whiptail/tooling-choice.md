# Выбор TUI-инструмента

Проверено 19.11.2026 на живых хостах (оба — Debian GNU/Linux 13 trixie).

## Факты о пакетах

| | `whiptail` | `dialog` |
|---|---|---|
| версия на ifw/dietpi | 0.52.25-1 | не установлен |
| Priority в Debian | **important** (входит в стандартную установку) | optional |
| Installed-Size | **61 КБ** (на dietpi 97 КБ, arm) | 493 КБ + `libdialog15` 263 КБ = **756 КБ** |
| зависимости к установке | 0 пакетов (уже стоит) | **2 пакета** (`apt-get -s`: `0 upgraded, 2 newly installed`) |
| есть на ifw | да | нет |
| есть на dietpi | да | нет |

`whiptail` стоит на обоих наших хостах без единого действия — неудивительно, у него
`Priority: important`.

## Возможности `whiptail` 0.52.25 (снято с `--help` на ifw)

Типы боксов: `--msgbox`, `--yesno`, `--infobox`, `--inputbox [init]`, `--passwordbox`,
`--textbox`, `--menu`, `--checklist`, `--radiolist`, `--gauge`.

Опции, которые нам нужны: `--defaultno`, `--default-item`, `--nocancel`, `--separate-output`,
`--output-fd <fd>`, `--scrolltext`, `--title`, `--backtitle`, `--clear`.

**`--form` отсутствует.** Это ограничение версии, и оно решает форму экранов (см. ниже).

## Что требуется от диалогов и чем это закрывается

| нужно для наших 39 вопросов | whiptail | dialog |
|---|---|---|
| да/нет с дефолтом | `--yesno` + `--defaultno` | то же + `--yes-label` |
| число с диапазоном (MTU) | `--inputbox` + проверка в цикле | `--inputbox` / `--rangebox` |
| выбор 1..N (патч, WARP, DNS) | `--menu` | `--menu` |
| свободная строка (домен, endpoint) | `--inputbox` | `--inputbox` |
| несколько флажков на экране | `--checklist` | `--checklist` |
| сводка перед установкой | `--textbox`/`--scrolltext` | `--textbox` |
| прочитать результат | `--output-fd 3` (**есть**) | `--output-fd 3` |
| коды выхода | 0 / 1 / **255** | 0 / 1 / **2** / 255 — код 2 (Help) лишняя ветка |
| несколько полей на одном экране | **нет** | `--form` есть |

## Альтернативы и почему отпадают

| вариант | почему нет |
|---|---|
| `gum` (charmbracelet) | статический бинарь, качать с GitHub на каждый VPS; в Debian его нет; тащит чужой артефакт в установщик |
| `fzf`, `peco`, `skim` | искатели списков: нет да/нет, нет валидации, нет чеклиста с состоянием |
| `zenity` | требует X11/Wayland, у нас только SSH |
| `bash select` + `read` | то, что уже есть: нет да/нет, нет валидации, 39 пунктов нечитаемы |
| `python` + `prompt_toolkit`/`npyscreen` | новый рантайм-зависимость, ломает правило «структура исходного setup сохраняется» |
| `dialog` | всё выше в таблице: optional, +756 КБ, 2 пакета, нет ни на одном нашем хосте |

## Решение: `whiptail`

1. **Ничего не устанавливаем** на наших хостах: он уже есть и на ifw, и на dietpi, и на любом
   Debian/Ubuntu с приоритетом important. Установщик и так ставит десятки пакетов — добавлять
   ещё один «optional» смысла нет.
2. **Меньше веток** — коды 0/1/255 вместо 0/1/2/255.
3. **Меньше кода** — API проще, ближе к «не перерабатываем логику».
4. Это классика установщиков (`raspi-config` и большинство русскоязычных установщиков), вид
   знаком пользователю.

**Решение пользователя (19.11.2026):** проверка наличия `whiptail` обязательна; если бинаря нет —
`apt-get install -y whiptail` (один пакет, 61 КБ), при неудаче — plain-режим `read -rp`.
Ориентир — актуальная версия **0.52.25** (Debian 13); версия пишется в лог, отдельного полигона
под другие версии не делаем. Исключение: `QUESTIONS_ONLY=1` пакеты не ставит и систему не меняет.

## Следствие для спеки

`--form` в whiptail 0.52 нет, поэтому экран «Network одним блоком» невозможен. Вариант A
(сохраняем структуру исходного `setup`) означает **по одному диалогу на вопрос в исходном
порядке** — 39 окон подряд, без группировки. Если хочется меньше окон, нужны либо `dialog`
(+2 пакета), либо принудительная склейка соседних однотипных вопросов, что меняет структуру
и требует отдельного согласия.

Открытый вопрос пользователю: 39 диалогов подряд (строго структура) или склейка соседних
однотипных вопросов в один экран (меньше окон, структура меняется)?
